# Jalons 29 à 31 — WhatsApp, SMS Orange et Web Push

## Jalon 29 : API WhatsApp Cloud

Le canal WhatsApp passe par l'API Meta WhatsApp Cloud
(`modules/whatsapp/`). Le client ne sait envoyer que du texte et des modèles
(`/messages`), jamais de vocal ni de média.

Le webhook `GET /api/v1/webhooks/whatsapp/` valide le handshake
(`hub.challenge` + `WHATSAPP_WEBHOOK_VERIFY_TOKEN`) ; les messages entrants
(`WhatsAppInboundMessage`) et les statuts de livraison
(`WhatsAppMessageStatus`) sont enregistrés de façon idempotente et répondent
200 rapidement, comme l'exige Meta.

`WhatsAppCloudApiAdapter` est branché sur le worker `process_notifications` :
une erreur permanente (téléphone non sur WhatsApp) marque la livraison sans
relance.

## Jalon 30 : canal SMS Orange (Côte d'Ivoire)

Le canal SMS passe par l'API SMS CI d'Orange (`modules/sms/`), OAuth 2.0 v3 :

- le token (3600 s) est réutilisé et renouvelé automatiquement sur l'erreur
  officielle *Expired credentials* (401, code 42) ;
- l'adaptateur normalise le numéro ivoirien en E.164, compte les segments
  (GSM-7/UCS-2) pour estimer le coût en FCFA, tronque les messages trop longs
  en conservant le lien et respecte la limite de 5 SMS/s ;
- chaque envoi est tracé (`SmsSendRecord`) avec le coût estimé et l'heure ;
- les accusés (`deliveryInfoNotification`) arrivent sur
  `POST /api/v1/webhooks/sms/orange/`, filtrés par liste blanche d'IP
  (`ORANGE_SMS_DR_ALLOWED_IPS`, vide = 503). Orange ne signe pas : la sécurité
  repose sur HTTPS, la validation stricte du payload et le `resource_id` comme
  secret d'intégrité non énumérable. Un doublon est absorbé et un échec
  (`DeliveryImpossible`) ne downgrade jamais un statut `DELIVERED`.

## Jalon 31 : Web Push et déploiement

### Web Push VAPID

`WebPushVapidAdapter` (`modules/notifications/adapters.py`) envoie via le
protocole Web Push standard : aucun fournisseur externe, le navigateur
s'abonne au push de son fabricant et ImmoLib signe avec sa paire VAPID. Le
TTL est de 7 jours (l'appareil hors ligne reçoit quand même la notification) ;
un abonnement expiré (404/410) devient une erreur permanente.

Côté navigateur (`apps/web/src/lib/web-push.ts`) : enregistrement du service
worker, abonnement `pushManager.subscribe` avec la clé publique VAPID encodée
en base64url, stockage de l'abonnement dans le localStorage et désabonnement
propre. L'écran Paramètres > Notifications pilote tout avec
`WEB_PUSH_CONFIGURED`.

### Infrastructure

- Blueprint Render (`infrastructure/render.yaml`) : base PostgreSQL + API
  Docker, migrations au démarrage, `/health/` comme health check.
- Sauvegardes chiffrées AES-256 (`backup.sh`), restauration (`restore.sh`) et
  commandes planifiées sous `flock` (`run-scheduled.sh` + `crontab-prod`).
- Reverse proxy nginx devant l'API (`nginx-app-immolib.conf`).
